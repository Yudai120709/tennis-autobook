# 都営テニスコート 監視・自動予約（GitHub Actions 版）

GitHub のサーバーで動くので、PCは閉じていて大丈夫です。動きは2つあります。

| 動き | タイミング | 内容 |
|---|---|---|
| ① 一斉予約 | 毎月21日 23:20 に起動 → 23:55 にログインし、空き状況画面を開いたまま待機 → **22日 0:00:01 に開始** | 翌月分から条件に合う枠を優先順にすべて予約（上限なし） |
| ② 毎時の監視 | 毎時7分 | 新しく空いた枠を通知し、条件に合う枠はすべて予約（上限なし） |

## 初期設定の条件（config.json）

- 公園：木場公園、猿江恩賜公園、亀戸中央公園（いずれも人工芝）
- 土日：すべての枠／平日：19時以降に始まる枠
- 祝日：**休日扱い**（全枠）
- 今日から6日後以降の枠だけ（キャンセル期限＝利用日の4日前より前に、通知を見て判断できるようにするため）
- オンライン支払いはしません。予約後の「オンライン支払い」の手続きには一切触らず、申込画面で支払方法を選ぶ欄が出たときは、オンライン決済ではない方を選びます
- 一斉予約の優先順：土日祝 → 日付の早い順 → 時間帯（9→11→13→15→17→19→7時）→ 公園（木場→猿江→亀戸）
- 取るコート数の上限：なし。ただし同じ日時に別の公園を重ねて取ることはシステム上できないため、その場合は優先順の高い方だけ取ります
- 待機中は2分おきに画面を開き直して、ログイン状態を保ちます

## セットアップ

1. GitHub で **Private** のリポジトリを作り、このフォルダの中身をすべてアップロードする
   （`.github/workflows/tennis.yml` が入らないときは「Add file」→「Create new file」でそのパス名で作成して中身を貼り付け）
2. Settings → Secrets and variables → Actions → New repository secret で登録する
   - `SPOREC_USER_ID`：スポレクの利用者番号
   - `SPOREC_PASSWORD`：スポレクのパスワード
   - 通知先（どちらか）：`DISCORD_WEBHOOK_URL`、または `GMAIL_USER`＋`GMAIL_APP_PASSWORD`（＋`MAIL_TO`）
   - Secrets は登録後に自分でも見られず、ログにも表示されません
3. Settings → Actions → General → Workflow permissions を「Read and write permissions」にする（状態ファイルの保存に必要）

## 最初に必ずリハーサルをしてください

初期設定は `"mode": "rehearsal"`（予約の**確定ボタンの直前で止まる**モード）です。

1. Actions タブ →「テニスコート監視・自動予約」→「Run workflow」→ task に **release_now** を選んで実行
   （待たずに、翌月分の空き枠でログイン〜申込画面まで進めます）
2. 終わったら、実行結果の画面下の **Artifacts → screenshots** をダウンロードし、各画面を確認
3. 通知に「リハーサルのため『○○』ボタンの直前で止めました」と出ていれば成功です。
   別の理由で止まった場合は、スクリーンショット（氏名・利用者番号は隠して）を見せてもらえれば修正します
4. 問題がなければ config.json の `"mode": "rehearsal"` を **`"book"`** に書き換えて保存 → 以後は本当に予約します

※ 申込画面から先はログインしないと見られないため、作成時に実際の画面では確かめていません。最初のリハーサルが動作確認を兼ねます。

## 設定項目

| 項目 | 意味 |
|---|---|
| targets | 監視する公園（コードは「公園コード一覧.txt」） |
| weekend_all / weekday_start_from | 土日は全枠／平日は○時以降に始まる枠 |
| holidays_as_weekend | 祝日を土日扱いにするか |
| days_from / days_ahead | 今日から○日後〜○日後までの枠を対象にする |
| auto_book.mode | `rehearsal`（確定直前で止める）／`book`（本当に予約） |
| auto_book.max_active | 自動予約した枠（まだ利用日が来ていないもの）の上限。`null` は上限なし |
| auto_book.max_per_run | 毎時の監視1回で予約する最大数。`null` は上限なし |
| auto_book.one_per_day | `true` にすると同じ日は1枠だけ取る |
| auto_book.players | 申込画面で利用人数を聞かれたときに入れる人数 |
| release.max_bookings | 22日の一斉予約で取る最大数。`null` は上限なし |
| release.login_minutes_before | 0時の何分前にログインして待機するか |
| release.preferred_start_hours | 一斉予約で優先する開始時刻の順 |
| release.enabled / auto_book.enabled | `false` でその動きを止める |

## 大事な注意

- **上限なしのため、条件に合う空きはすべて予約します**（来月分の候補はおよそ250枠）。不要な予約は**利用日の4日前までに自分でキャンセル**してください。それを過ぎるとペナルティになります。予約できたときの通知に、キャンセル期限を書いています
- 1件の予約に数十秒かかるので、0時直後に取れる数には限りがあります。後ろの候補ほど、ほかの人に先に取られやすくなります
- 自分で手動で取った予約は、スクリプトには分かりません（自動予約の上限の数には入りません）
- 次の場合は、自動では先に進まず、止まって通知します
  - ログイン時に画像認証（reCAPTCHA）が有効になっていた
  - SMS などの追加の認証を求められた
  - ペナルティの警告が出た
  - オンライン決済以外の支払方法が選べなかった
  - 押すボタンが判断できなかった
- **画像認証などの仕組みを回避することはしていません。** 運営側がそれを有効にした場合は、自動予約はできなくなります
- GitHub の定期実行は数分〜十数分遅れることがあります。そのため一斉予約は23:20に起動して、中で0時ちょうどまで待つ作りにしています。ただ、0時直後はシステムがとても混雑するので、確実に取れるわけではありません
- 実行時間の目安：毎時の監視が約1〜2分、一斉予約が月1回あたり40〜60分です。Private リポジトリの無料枠（月2,000分）にはおおむね収まる見込みです。Settings → Billing で実際の使用量を確認してください
- 利用者登録はひとり1件です。個人利用の範囲で、アクセス間隔を縮めずに使ってください

## 止めたいとき

Actions タブ → ワークフローを選ぶ → 右上「…」→「Disable workflow」
